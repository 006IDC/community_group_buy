# 架构与数据边界

## 稳定身份

- 模块：`addon`
- 插件名：`CommunityGroupBuy`
- 目录：`community_group_buy`
- 入口：`CommunityGroupBuy.php / CommunityGroupBuy`
- namespace：`addon\community_group_buy`
- 用户端接口前缀：`/console/v1/community_group_buy`
- 管理端接口前缀：`/{后台目录}/v1/community_group_buy`

目录、入口类、`$info.name`、namespace 和路由 `_plugin` 可按 V10 命名规则稳定互转。身份发布后不可改名。

## 业务流程

1. 管理员配置普通团和 0.1 元团的商品白名单与风控参数。
2. 用户在会员中心选择模式和商品；普通团再选择 3、5 或 10 人。
3. 服务端重新校验白名单、商品状态、人数、预算和用户限制，创建团与团长成员关系。
4. 开团结果返回后，客户端读取分享元数据并生成链接、二维码与宣传图。
5. 其他用户登录后主动参团；分享参数不直接写成员关系。
6. 满员后，服务端为每名成员创建绑定本人和商品的一次性官方优惠码。
7. 下单前再次校验归属、商品、数量、新购类型与价格上限；付款后只校准首次付款语义。
8. 取消、删除、退款和过期任务按状态释放或保留权益与补贴预留。

## 数据所有权

插件只拥有团与成员两种 V10 官方表无法等价表达的事实。白名单、优惠码、订单、Host 与审计继续由官方数据源负责，详见 [DATABASE.md](DATABASE.md)。

分享 URL 只包含当前 V10 `plugin.id` 和团 ID。二维码矩阵从宿主已有组件读取，宣传图在浏览器 Canvas 中绘制，不建立分享或媒体表。

## 一致性与并发

- 发团使用账号级锁和唯一 `request_key`，网络重试不会重复开团。
- 参团锁定客户、团记录和成员数量，唯一键阻止同团重复加入。
- 满员、发码、下单准备、订单绑定和取消释放在事务中完成。
- 0.1 元团在发团时原子预留 10 人全部预计亏损。
- Hook、支付与退款路径按官方订单 ID 和成员状态实现幂等。
- `upgrade()` 采用探测后执行的迁移，可在中断后重试。

## 权限与公开数据

- 用户接口经过 `CheckHome` 和 Addon 用户权限；写接口增加 `RejectRepeatRequest`。
- 管理接口经过 `CheckAdmin`，查看与管理权限分离。
- 用户端列表、详情和“我的拼团”分别组装字段白名单。
- 前台不返回客户/订单/优惠码 ID、成本率、补贴参考价、预留亏损或请求幂等键。
- 未知内部异常映射为通用文案与稳定错误编号，原始异常只进入官方审计日志。

## 价格语义

- 普通团固定 9/8/7 折，成本按售价 65% 估算。
- 已有客户等级价格更低时保留更低价，不重复叠减。
- 0.1 元团固定 10 人且每人首次开通均为 0.1 元。
- 团购只调整首次开通权益，不修改续费价格。
