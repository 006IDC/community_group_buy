# ZJMF-CBAP V10 合规说明

## 合规矩阵

| V10 要求 | 实现 |
| --- | --- |
| Addon 目录命名 | `community_group_buy`，小写 snake_case，字母开头 |
| 入口与全局身份 | `CommunityGroupBuy.php / CommunityGroupBuy`，与 `$info.name` 一致 |
| namespace | `addon\community_group_buy` |
| PHP 兼容 | 运行代码兼容 PHP 7.3；CI 同时检查 PHP 7.3 和新版本 |
| 安装/升级 | `install()`、`upgrade()` 明确返回 `true`，迁移幂等，无条件 DROP 不用于新安装 |
| 卸载 | 明确保留经营与订单归因数据 |
| Hook | 入口类公有业务方法仅包含生命周期和已验证 Hook；内部助手均为 private |
| 路由 | 显式 `route.php`，后台动态使用 `DIR_ADMIN` |
| 登录与权限 | 用户端 `CheckHome`，后台 `CheckAdmin`；权限文件分别使用 V10 所需的完整/短控制器规则 |
| 参数与重复提交 | `ParamFilter`；发团/参团/后台保存增加 `RejectRepeatRequest`，业务层另有锁和唯一键 |
| 响应 | 使用 V10 常见 `status/msg/data` 外层，同时对未知异常做公开映射 |
| 金额 | 使用 DECIMAL 字符串和 BCMath，不用浮点做最终财务比较 |
| 数据库 | 不修改核心表结构；只新增团、成员两张必要旁挂表 |
| 官方数据复用 | 配置、优惠码、订单、Host、审计和插件 ID 均复用官方数据 |
| 模板 | 提供根兼容模板以及 `pc/default`、`mobile/default` 同伴模板，三份保持字节一致 |
| 静态资源 | PC/Mobile 和兼容入口使用同一版本参数 |
| 页面动作 | 保存、刷新、发团、参团、复制和下载均有 loading/success/error 反馈 |
| 主写/刷新语义 | 主写成功而后续刷新失败时明确提示“已保存/已发起，但刷新未完成” |
| 分享 | 动态读取当前官方插件 ID；优先使用可信 `clientarea_url`；不新建分享表 |
| 核心修改 | 无 |

## 版本证据边界

当前源码来源功能已在 V10 10.4.6 契约下验证；开源身份 1.0.0 已完成本地语法、合同、金额、敏感信息、模板一致性和安装包结构检查。不同 V10 10.x 小版本可能在模板后缀、主题变量、权限升级和官方表字段上存在差异，部署前必须在隔离站复测。

不能只凭以下结果宣布生产兼容：

- ZIP 可以解压。
- 静态插件页返回 HTTP 200。
- 数据库最终出现记录。
- 后台按钮可见。

真实验收还应覆盖安装/启用/禁用/升级、普通与受限账户、PC/Mobile、发团/参团/付款/取消/退款、重复点击、结果未知、缓存刷新和服务端日志。

## 不包含的能力

- 不修改 V10 Core。
- 不提供 V10 本体或官方优惠码插件。
- 不绕过登录、用户权限或商品白名单。
- 不承诺 0.1 元模式首月盈利。
- 不保存服务端宣传图、明文优惠码副本或支付凭据。
